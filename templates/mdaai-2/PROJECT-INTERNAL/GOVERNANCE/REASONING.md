# Reasoning and coordination economy

Optimize total time, tokens, rework, and escaped defects—not token count alone. Read the nearest instructions, the active task, and named evidence; expand context only when a concrete uncertainty requires it. State facts, hypotheses, decisions, evidence, and next actions distinctly in compact work notes. Preserve preconditions, authority, uncertainty, and failure semantics; omit private reasoning transcripts and repeated narrative.

Use the least expensive model/effort that can reliably decide the next step: bounded lookup or deterministic editing at lower effort; architecture, security, ambiguous causality, and final integration at higher effort. Compare alternatives once, record the accepted decision, and reopen it only for named new evidence or a changed requirement. Use the cheapest decisive check first, then broaden to affected composition and real runtime. Stop checking when the risk and acceptance contract are supported; do not repeatedly run heavy suites in parallel against the same shared outputs.

When delegation is authorized and useful, give workers narrow inputs, exact path ownership (including tests and docs), an acceptance check, and a short result contract. Workers do not edit shared status or integration files. The coordinator owns contracts, integration, conflict resolution, and registry transitions. Parallel work is inappropriate when tasks share mutable files, environment, or a serial causal dependency.

Automate repeatable, decidable checks with small tested tools, but do not claim they replace architectural judgment or actual runtime observation. Clear English with defined notation is the default. “Neuralese,” unverified compressed language, or switching to Chinese merely to save tokens is not a governance rule: tokenization and comprehension vary, and there is no measured project evidence of net gains. If a shorthand is used, define it and measure total correctness and rework, not just prompt length.
